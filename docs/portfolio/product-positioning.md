# FAB ONE — 제품 포지셔닝과 기술 스토리 (A05 초안)

> **문서 상태:** REVIEW · 2026-10-15 · A05 / [Issue #5](https://github.com/Junebooky/semi_fab/issues/5)  
> **제품 상태:** 기획·초기 구축 · 합성 Etch 시나리오를 목표로 한 시뮬레이션 프로젝트 · **실제 FAB/장비 미연결**  
> **검토자:** A01(제품·도메인), A02(구현 가능성), A03(사용자 경험), A04(증빙·QA)
>
> 이 문서는 **제품이 이미 제공하는 기능 목록이 아니라 포지셔닝 제안**이다. 실제 구현/시연/검증을 나타내는 문장은 [기술 주장·근거 매트릭스](./claims-evidence-matrix.md)의 승격 기준을 충족하기 전에는 사용하지 않는다.

## 1. 핵심 포지셔닝

### 제안하는 한 줄 설명 (현재 사용 가능)

**“반도체 Etch 공정의 가상 이상 상황을 출발점으로, 데이터 해석·영향 Lot/Wafer 조사·조치 이력의 문제 해결 과정을 소프트웨어로 재현하려는 엔지니어링 시뮬레이션 프로젝트.”**

### 장기 제품 비전 (목표 표현으로만 사용)

“공정·설비·PI·품질·제조·수율 업무에서 사용하는 데이터와 엔지니어링 지식을 하나의 조사 흐름으로 연결하는 워크스페이스.”

- **현재 확인된 사실:** 공개 `main`의 README는 방향/목표와 “기획 / 초기 구축” 상태를 명시한다. 실행 가능 애플리케이션·시뮬레이터·테스트 결과는 이번 점검의 확인된 증빙에 없다.
- **지향하는 데모:** 합성 Etch 장비 이상 신호 → 관련 공정/설비 계측값 비교 → 동일 시간대·장비·챔버·공정 이력을 기준으로 Lot/Wafer 후보 탐색 → 조사 가설·근거·조치 이력 기록.
- **추론 제한:** 시뮬레이션에서 이상 신호와 Lot의 동시성/상관관계를 보여도 결함 판정, 영향 확정, 근본 원인 규명, 실물 장비 조작을 증명하지 않는다.

## 2. 해결하려는 문제: 기능 나열이 아닌 탐색 여정

**일반화한 업무 문제 가설:** 제조 이상 조사는 설비 이벤트, 계측 시점, Lot/Wafer 계보, 공정 조건, 품질 데이터를 함께 보며 판단해야 한다. 정보가 다른 화면·스키마·역할로 분리되면 원인 가설을 설명하고 재검토하기 어려울 수 있다. 이것은 **문제 가설**이며 실제 업체 조사나 사용자 인터뷰 결과로 제시하지 않는다.

| 단계 | 엔지니어가 묻는 질문 | FAB ONE에서 목표로 하는 경험 | 필요한 검증 |
| --- | --- | --- | --- |
| ① 이상 관찰 | 어느 지표가 언제 어떤 기준을 벗어났나? | 합성 설비·센서 시계열, 단위, 수집시각, SPC/FDC 경고와 기준표시 | A01 경보 정의, A02 데이터 계약, A04 임계값 테스트 |
| ② 정황 확인 | 어느 장비/챔버/레시피/런에서 발생했나? | 이벤트와 공정·계측 기록의 시간/ID 매핑 | 식별자/FK, 타임존, 결측치 처리, 재현성 |
| ③ 영향 후보 조사 | 어떤 Lot/Wafer가 해당 조건에 노출됐을 가능성이 있나? | 시뮬레이션 이력 기반 **후보군** 필터링 및 근거 표시 | lineage/시간 겹침 로직, false match/누락 테스트 |
| ④ 해석·협의 | 패턴이 원인인지, 단순 동반 현상인지? | 가능 가설, 반증 증거, EKL 개념·수식 설명 | A01 도메인, A04 경고 표현 및 수식 교차검증 |
| ⑤ 조사 이력 | 무엇을 확인했고 다음 담당자가 무엇을 볼까? | 로컬·시뮬레이션 사례 기록/상태/근거 링크 | A02 저장 정책, A04 데이터 손실·동시 수정·권한 검증 |

**주의:** 실제 생산 Hold/Release 명령, 임의 자동 조치, 공식 승인·감사 추적은 현재 범위에서 제공하거나 홍보하지 않는다.

## 3. 대상 독자별 메시지와 직무 경계

| 독자/현업 기능 | 그들이 확인할 역량·관점 | 시연으로 보여주려는 **학습/설계 능력** | 이 프로젝트로 증명할 수 없는 것 |
| --- | --- | --- | --- |
| 공정 엔지니어 | 공정 변수·레시피·계측 데이터 해석 | Etch 조건/계측·시간 정합성·가설 구분을 모델링한 이유 | 실제 레시피 개발·최적화·양산 경험 |

| PI/수율 분석 | 단계별 공정 연결·결함 분포·수율 해석 | Lot/Wafer 연결관계·분석 단위·가정의 투명성 | 실수율 개선, 양산 데이터 기반 인과분석 |

## 4. 차별화는 '성과'가 아닌 검증 가능한 설계 선택으로

1. **이벤트 중심 End-to-End 사용자 여정:** 단일 차트가 아니라 “이상→정황→영향 후보→가설→기록”을 연결하려는 정보구조. 제품 구현 전에는 ‘차별적 성능’이 아닌 **기획 방향**.
2. **Engineering Knowledge Layer:** 화면 내 기술용어·수식·단위·가정·참고 문헌을 같은 맥락에서 설명하려는 구조. 구현된 AI 자동 전문가 판단으로 표현 금지.
3. **재현 가능성을 설계 요구로 선제 정의:** 합성 데이터의 seed/생성기 버전/시나리오·시간/입력 근거/테스트를 연결하도록 계획. 검증 전 ‘완전 재현’ 금지.
4. **현업 오해를 막는 출처·권한 표기:** `SYNTHETIC / SIMULATION`, 측정 기준, 추정 경고, 가짜 역할 전환과 인증의 차이를 명시할 계획.
5. **시각적 커뮤니케이션:** Toss의 사용성 원칙을 연구하되 FAB ONE의 독자적 아이콘·3D 클레이 에셋을 사용. 현재 검증된 사용자 시간 절감/정확도 향상 수치는 없음.

위 항목이 **경쟁사 대비 우월함을 입증한 것**은 아니다. 비교 성능·시장 조사·사용자 테스트가 없으면 경쟁 우위 수치나 “유일한 플랫폼”이라고 쓰지 않는다.

## 5. 채용용 스토리텔링 프레임 (수정 가능한 대본)

**문제 정의:** “공정 이상 분석에서 센서 값, 공정 이력, 영향 대상, 조사 근거를 분리해 보면 어떤 의사결정 경로가 필요한지 설명하기 어렵다고 판단했습니다.” → **현업 발견 사실**이 아닌 프로젝트의 설계 가설.

**설계 선택:** “그래서 가상의 Etch 장비 이상을 사례로 정의하고, 관찰→연관 이력→영향 후보→검증해야 할 가설→이력 기록의 순서로 제품을 기획했습니다.”

**기술 증빙 (현재):** “현재 공개된 결과는 초기 README, 작업 Issue, 제안 단계 ADR, 실행 전 QA 전략 문서입니다. 실행 가능한 시뮬레이터 및 수치 검증 성과는 아직 제시하지 않습니다.”

**기술 증빙 (미래, 조건부):** 실제 구현 SHA, 실행 명령, 입력 fixture/seed/hash, 시연 캡처, A04 PASS 테스트, A01 도메인 검수 링크가 있으면 “해당 버전에서 구현·재현/검증했다”로 업데이트.

**한계:** “합성 데이터 기반 학습·시연으로, 실제 제조 현장 데이터·장비/시스템 연동·생산 성과는 검증되지 않았습니다.”

### 인터뷰에서 소유자 기여를 구분하는 방식

- 소유자: 문제와 목표 정의, 범위·우선순위·아키텍처 의사결정 승인, 기술·도메인 검토 요청, 결과 평가, 최종 책임 (**실제 수행 확인되는 항목만 주장**).
- AI 에이전트: A01 기획/도메인, A02 구현, A03 디자인, A04 QA, A05 문서 기여를 실제 Issue·PR·커밋으로 추적.
- “모든 코드를 단독 직접 작성했다”, “현업 데이터를 확보했다” 등의 확인되지 않은 개인 업적은 쓰지 않는다.

## 6. 시연 콘텐츠 사용 게이트

- **현 단계 허용:** 제품 목표·다이어그램·과업 계획과 “기획 시나리오(Concept)” 명시된 목업. 실제 동작 UI처럼 편집하거나 녹화하지 않는다.
- **A02 동작 버전 이후:** 검증 가능한 실행 URL/명령과 커밋 SHA를 함께 노출하고, 시연에 “합성 데이터” 표시.
- **A04 QA 이후:** 확인한 경로·계산·한계·실패 사례를 테스트 ID/로그/증빙으로 연결.
- **실제 환경:** 별도의 현장 승인·검증 근거가 없는 한 “실 FAB 적용” 문구는 사용하지 않는다.
